<objective>
Replace the verbatim script with a context-biased live agent, and in the same change fix the
agent going silent after its opening line.

Plan 02-01 proved one live beat: the session mints, WebRTC connects, and the agent speaks
`BEATS[0].line` word for word. It then never speaks again — by design, because the runner issues
exactly one `response.create` per session and `create_response: false` stops the server responding
on its own. The original 02-02 would have fixed that by issuing one verbatim `response.create` per
beat. Kaleb rejected that on 2026-08-29: a fixed paragraph costs a full TTS round-trip before any
audio (measured ~9.6 s for the greeting), and an agent that cannot react to what was actually said
reads on camera as a recording with a microphone in front of it.

This plan does the opposite. The session's `instructions` become the whole of `lib/agent-context.md`
— the shop, the catalogue, the confirmed facts, the tone rules, the shape of the conversation — and
the runner stops dictating words entirely. It issues a *bare* `response.create` when the owner
finishes a turn, and the model answers in its own words, unable to say anything outside that file.

The screen does not change. `FRAMES`, the "Locked in" rows, the context cards, the two pills and Go
live stay exactly as hardcoded as they are today, advanced by the beat table and the canned tool
handlers. **The agent's words become live; the screen does not.**

Output: a live session where the owner can talk normally, get a natural short reply every turn, and
watch the page walk A → G on rails.
</objective>

This is the one-line-of-intent fix, plus the guards that make it safe.

**Speak on the owner's turn, not once per session.** Today `enterBeat` sends the only
`response.create` in the codebase and is guarded to run once. Split those apart:

- On the session going live, issue one bare `response.create` so the agent opens the conversation.
- On every qualified `speech_stopped` thereafter, issue another bare `response.create`.

**Bare** means the payload carries no `instructions` and no per-turn wording of any kind — the
session instructions from Task 1 are the only thing shaping the reply. Delete `verbatim()` from
`lib/agent-script.ts` along with its call site; leave no dead helper behind.

**Drop `conversation: "none"`.** The tracer set it so the growing transcript could not nudge the
model off its verbatim line. That reasoning is now inverted: an out-of-band response cannot hear
what the owner just said, and an agent that cannot hear is worse than a scripted one. Responses join
the conversation from here on.

**Never two responses in flight.** Track the active response between `response.created` and
`response.done` and suppress any `response.create` issued while one is open — the API rejects the
second with `conversation_already_has_active_response`, and a rejected turn is dead air on camera.
Suppression must be silent and must not consume the turn's frame advance.

**Split the reply threshold from the advance threshold.** These are two different questions and the
tracer conflated them:

- `MIN_REPLY_MS` (new, 400 ms) — below this, the turn was a cough and gets no reply.
- `MIN_SPEECH_MS` (1200 ms, unchanged) — below this, the frame does not advance.

So a short "ya lah" gets a spoken answer without moving the take, and a cough gets neither. Both
thresholds measure the same corrected span: wall-clock between the VAD events **minus**
`VAD_SILENCE_DURATION_MS`. Do not re-derive that subtraction; it is why the guard works at all.

Keep the echo rejection exactly as it is — speech beginning while the agent talks, or within
`ECHO_GRACE_MS` of it stopping, is the agent's own voice and is discarded before either threshold is
consulted.

**Operator keys, absolute overrides that work in every state** (VOICE-06). Extend the existing
keyboard effect in `hooks/useOnboardingState.ts` — same effect, same structure, one more branch —
so the arrows keep their exact Phase 1 meaning and `R` re-prompts: `R` issues a fresh bare
`response.create` (nudging a stalled agent to speak again) and, if the session has dropped,
re-attempts the connection first. Every new key must no-op safely with no session and no throw.

**Operator event log.** In `hooks/useRealtimeSession.ts`, keep the last N raw events in a ring buffer
and expose it, so the model's own output transcript can be inspected during a take. It is never
rendered on stage; plan 02-03's status chip is its only consumer.

Stop setting the on-screen agent line from the beat's `line`. Under context bias the spoken words and
the printed words are no longer the same string, and the printed one is the deterministic Phase 1 copy
the design brief marks final. Remove `agentLine` from `BeatRunnerApi` and let
`components/Onboarding.tsx` derive it from `frame.agentLine` as it did in Phase 1 — one less
non-deterministic thing on camera, and it deletes the `AUDIO_TIMEOUT_MS` blank-screen risk with it.
Keep `AUDIO_TIMEOUT_MS` itself: no audio within that window of a `response.create` still means a
dropped session and still falls back to scripted mode.
  </action>
