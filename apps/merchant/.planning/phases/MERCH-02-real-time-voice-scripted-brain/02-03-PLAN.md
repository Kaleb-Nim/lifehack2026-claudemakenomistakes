the chrome they need to run a take, and make every failure path fall silently back to the Phase 1
demo.

  <action>
Implement all seven handlers in `TOOL_HANDLERS` and make the runner dispatch them.

Each handler takes its arguments and returns a canned payload assembled from `lib/merchant-data.ts`
through the exported `FRAMES` array and the exported card, hero, product and live-line constants. The
mapping CONTEXT.md fixes: the website search resolves to the site card; a source read resolves to the
price-list, flyer or photos card selected by the file argument; locking a fact resolves to the
matching log line on the target frame; flagging a conflict resolves to one of the three flag lines;
resolving a flag resolves to its struck counterpart; asking a pill resolves to the F or F2 pill pair;
going live resolves to the live line. Because the log-line constants are module-private, read them
back off `FRAMES[i].log` by mark and text rather than importing them.

Make the handler's return value the thing that moves the page. The runner fires a beat's tool calls
on beat entry, honouring each call's optional millisecond offset within the beat, and calls `go()`
for the next frame — or `setLive(true)` for the go-live tool — as a consequence of the handler
returning, not on a bare timer. The rendered visuals stay byte-identical to Phase 1 because the frame
snapshot is what renders; what changes is that a tool result is what selects it. That is the seam
SCRIPT-03 asks for and the reason Phase 5 is a handler swap.

Keep the de-duplication guard from plan 02-02 in front of the dispatch, so a model-emitted call
matching one the runner already fired for the current beat is accepted and ignored rather than run
twice.

**Scroll the read source into view.** Phase 1's verification carried this to us: state C genuinely has
around 891 px of Context-column content in a roughly 791 px box, and the photos card ends mid-line on
camera because nobody scrolls during a take. The beat runner already knows which source the agent is
reading at each beat, so the scroll becomes motivated rather than incidental, and it avoids editing
extract copy the design brief marks final.

When `read_source` fires, record the file it names as the active source. Scroll that source's card
into view once the card is no longer in the reading set — that is the moment its height settles, and
for the photos card at beat C it is the same moment it expands, roughly 8.5 s into the beat. Scrolling
at tool-fire time instead would scroll to the wrong height.

Resolve the scroll container at call time by walking up from the card element to the nearest ancestor
whose scroll height exceeds its client height. After commits `6c7dce4` and `108d40b` that is `.cards`
or `.right`; resolving it dynamically means the concurrent session's CSS work cannot break this.
Compare the card's bounding box against the container's and scroll the container by the difference
with smooth behaviour, with a small padding. Scroll only that container — never the page and never
the `.stage`. When the card is already fully inside the container's box, do nothing at all: a jitter
on an already-visible card reads as a bug on camera.

Reach the card element through a callback ref keyed by the card's file, stored in a `Map` — this is
permitted JSX edit (f), an added `ref` attribute on the existing `.card` button and nothing else. No
class name changes, no wrapper element, no CSS.

The scroll must never run in `?mode=scripted`; that path has no beat runner, so guard it structurally
rather than with a flag check inside the scroll helper.
  </action>

  <action>
Create `components/OperatorChrome.tsx` exporting `Teleprompter`, `StatusChip` and `overlayBandPx`.
Both panels are operator-only chrome. Mount them inside `.viewport` as siblings of `.stage`, fixed to
the viewport corners — the teleprompter bottom-left, the chip top-right — so they sit in the
letterbox margin outside the scaled stage and can never overlap stage content. Style them entirely
with inline styles in the deliberately off-brand palette the UI-SPEC fixes: a dark translucent panel
on white mono text, at 13px, with the non-brand status-dot colours. Never use the accent token and
never add a class or a custom property. The operator must never be able to mistake either panel for
page content, and the camera must never see either one.

**The margin these panels live in exists only when the viewport's aspect ratio differs from 16:9 —
scale is irrelevant.** The fit is `min(w/1920, h/1080)`, so on a 16:9 viewport both ratios are equal
and the scaled stage fills both axes exactly, at any size. A 2560x1440 window scales to 1.333, above
one, with zero margin; a 1366x768 window scales to 0.711, below one, with 0.3 px per side. Export
`overlayBandPx(width, height)` returning the total vertical and horizontal bands as
`height - 1080 * min(width/1920, height/1080)` and `width - 1920 * min(...)`, evaluate it live on
resize, and have the teleprompter render a warning row when the larger of the two is under 24 px so
the operator finds out before rolling rather than in the edit. Never infer the band from a scale
value.

`Teleprompter` renders the beat number over the total, the owner's cue for the current beat, a mic
glyph that gains a slash when muted, and a connection dot coloured by session phase — green live,
amber connecting, grey scripted or fallback, red error or denied. The owner's cue truncates at 180
characters plus an ellipsis inside a 360px max width; this is an explicit rule, not silent clipping,
and the operator is assumed to have the full script on paper or a second monitor. At the final beat
there is no next line, so render the exact string `— end of script —`. If the script module yields no
beats at all, render `Script unavailable` rather than a blank or crashed panel — the same copy covers
a malformed module. If a beat is missing its owner cue, render the counter and the dots normally with
an empty line region rather than failing the panel.

`StatusChip` renders only on a session state change, never in the steady connected state and never for
an ordinary first connect. Its copy differs by cause, because the operator's fix differs: a drop, an
ICE failure, a missing or invalid key or a mint failure all read
`Voice dropped — beat {n} continuing in scripted mode · press R to retry`; a mic denial reads
`Mic permission denied — scripted mode · press R to retry`. It auto-hides four seconds after a
successful reconnect. A deliberate `Esc` drop is not a failure, so it reads `Scripted mode (Esc)`
persistently, with no retry hint and no auto-hide.

Neither panel is mounted under `?record=1` — absent from the DOM, not hidden, so neither appears in a
screenshot, a recording or a DOM inspector during the take.

Extend the existing keyboard effect in `hooks/useOnboardingState.ts` with two more branches
alongside the arrows, space and the `R` added in plan 02-02: `M` toggles the mic mute, whose only
feedback is the teleprompter's mic glyph, and `Esc` deliberately drops to scripted mode. Neither key
has any camera-facing affordance, by design. All five keys must no-op safely with no throw and no
visible glitch when there is no session to act on — pressing `M` on a freshly loaded page before the
orb has ever been tapped is the case to check.

**Silent fallback, everywhere.** Make every failure path resolve to the Phase 1 scripted demo at the
current beat with nothing rendered on the camera-facing stage: no key configured, a mint failure, a
WebRTC or ICE failure, a mic denial, a data-channel close mid-take, and no audio within
`AUDIO_TIMEOUT_MS` of a `response.create`. Each sets the matching failure value, the orb falls back to
the untouched Phase 1 `frame.orb` / `frame.orbLabel` derivation, and the chip tells the operator
which one happened. `R` re-attempts the session from the current beat. Voice remains the default
mode and key presence is probed by attempting the mint on the first user gesture — never by an
endpoint that reports whether a key exists.

Add the `overlayBandPx` assertions to the existing test file; they are pure arithmetic and cheap, and
they are the only thing standing between us and a retina capture that silently loses both panels.
  </action>
