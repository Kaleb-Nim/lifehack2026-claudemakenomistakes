## The reported bug: "after its opening it doesn't reply no matter what I do or say"

**This is not a bug in the Realtime API, the session config, the mic, or VAD. It is the 02-01
tracer's scope boundary, behaving exactly as written.**

Evidence, all verifiable in seconds:

1. `grep -rn "response.create" lib hooks app components` returns **exactly one** send site —
   `lib/beat-runner.ts:87`, inside `enterBeat`.
2. `enterBeat`'s only call site is `lib/beat-runner.ts:152`, guarded by
   `if (session.phase === "live" && currentBeatRef.current === null)`. `enterBeat` sets
   `currentBeatRef.current` on its first line, so that condition is true **exactly once per
   session**.
3. The session is minted with `create_response: false` (`lib/agent-script.ts` → `TURN_DETECTION`),
   which is what stops the model responding on its own. That flag is load-bearing for the scripted
   brain and is working correctly.

(1) + (3) together mean the agent can speak **once per session and never again**, regardless of what
the owner says. The page still advances a frame on a qualified `speech_stopped` — that part works —
but no second `response.create` is ever issued, so there is no second utterance.

The tracer's own header comment says so:

> "Progressing the runner's OWN beat cursor into subsequent beats (so they also get spoken) is plan
> 02-02's 'full beat progression' — deliberately not wired here, so this plan's single
> `response.create` stays observably singular."

**The fix is plan 02-02's job, and it is one line of intent:** issue a `response.create` when the
beat advances, not only when the session goes live.

## Fixes landed after the tracer merged — do not regress

- **`34a85cf`** — the agent was cutting itself off ~200 ms into every line. Its own audio fed back
  through the speakers, server VAD read it as an owner turn, and the server flushed the output audio
  buffer. `interrupt_response: false` does **not** prevent this: it stops the *response* being
  cancelled, not the *audio* being flushed, so `response.done` still arrived with a full transcript
  while nothing was audible. Fixed by explicit `echoCancellation`/`noiseSuppression`/
  `autoGainControl` constraints plus a hard mic gate that disables the local track while the agent
  speaks. Measured 0.2 s → 9.6 s. **Deliberate consequence: barge-in is gone.**
- **`34a85cf`** — the min-speech guard never worked. Server VAD only emits `speech_stopped` after
  `silence_duration_ms` (900 ms) of quiet, so the raw span over-reported by that much: a 400 ms
  cough measured ~1300 ms and cleared the 1200 ms guard built to reject it. Now subtracted, with
  `TURN_DETECTION` shared between route and runner so they cannot drift.
- **`f78245e`** — `PRODUCT_NAME` was rendering the literal string `[PRODUCT NAME]` in the header on
  camera. Now `Pluto`, per `docs/CANONICAL-DEMO-DATA.md` §1.
